## Outstanding findings

### High priority: draft loss protection is not shared

`switchView` and `beforeunload` guard quotation edits only. Company/item forms can be regenerated without equivalent protection. Company draft loss was reproduced in the preceding UX audit using an unsaved sample name. Add consistent draft preservation and leave confirmation; do not silently auto-save master data.

### High priority: receivables filter label contradicts implementation

The filter reads “받을 금액 있는 것만”, but `arRows()` includes `open !== 0`, including negative balances. The sample UI showed negative entries under this setting. Decide explicitly between positive-only receivables and a separately named nonzero-balance view. Do not change the financial calculation merely to conceal the discrepancy.

### Medium priority: touch targets remain too small

Measured at 390px and/or 320px:

| Control | Height |
| --- | ---: |
| Payment row delete | 26px (also 26px wide) |
| Quote filter reset | 30px |
| Quote all-dates | 33px |
| Customer material type tab | 35px |
| Item add-option | 38px |
| Quote add-row / batch-options | 37.5px |
| Quote add-delivery / add-payment | 39px |

Use a consistent mobile hit area, e.g. 44px minimum, including icon-only actions. Search input internal line heights on PC were not classified as touch-target failures because their enclosing controls supply the hit area.

### Medium priority: product identity omitted in shortage warning

`quoteShortage()` builds its label from item.name, color, and spec, omitting item.code. The inspected quote warned “셰프복 · WH · 3XL” even though JK_TEST_1 exists. Same-name items remain ambiguous at a decision point.

### Medium priority: date presentation still inconsistent

Company transaction history formats dates using `slice(2)`, producing `26-09-02`; other transaction views use four-digit years. Preserve stored dates and standardize presentation.

### Newly reproduced high-priority defect

`deleteQuote`, `deleteCompany`, `deleteItem` and `deletePayment` remove their local record before persistence finishes. A false save result does not restore it. The local list can therefore disagree with the server after a failed deletion. Tests used only synthetic VM fixtures: no production record was deleted.

Stock-restoration failure correctly blocks quote deletion, but a later failure saving the quotation deletion is not protected. Fix persistence ordering/rollback and verify multi-step failure handling before release.
