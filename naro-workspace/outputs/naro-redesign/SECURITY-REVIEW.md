## 알려진 한계 (받아들인 것)
- 승인 대기 화면은 브라우저 쪽 장치 — 우회해도 자기 저장소만 쓸 수 있음.
- 승인을 취소해도 이미 열려 있는 화면은 다음 로그인 때 막힘.
- 업무 화면(옛 코드)은 인라인 스크립트를 허용(CSP 'unsafe-inline'). 주입 시험은 통과했지만, 새 화면을 만들 때도 사용자 글자는 반드시 escapeHtml/textContent로.

## 사장님이 콘솔에서 할 일 (무료)
1. **관리자 계정 보호** — onlysh4sh@gmail.com의 NARO 비밀번호를 다른 곳에서 안 쓰는 긴 비밀번호로. Gmail·GitHub 계정은 2단계 인증.
2. **GitHub 2단계 인증** — 배포 열쇠(NARO_FIREBASE_DEPLOY_KEY)가 GitHub에 있다. GitHub 계정이 뚫리면 배포가 넘어간다.
3. **배포용 서비스 계정 권한 최소화** — Google Cloud 콘솔 → IAM → 배포에 쓰는 서비스 계정의 역할이 'Firebase 호스팅 관리자'만인지 확인(소유자·편집자면 줄이기).
4. **API 키 사용처 제한** — Google Cloud 콘솔 → API 및 서비스 → 사용자 인증 정보 → Browser key → 애플리케이션 제한: 웹사이트, `https://naro-biz.web.app/*`, `https://naro-biz.firebaseapp.com/*`. (옛 시스템이 다른 주소에서 이 키를 쓰고 있다면 그 주소도 추가)
5. **인증 허용 도메인 정리** — Firebase → Authentication → 설정 → 승인된 도메인: 쓰지 않는 주소 삭제.
6. (나중에) **앱 체크** — 로봇 가입 차단. 코드 작업이 필요해 판매 직전에 함께 진행.
